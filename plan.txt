# Government Customer Segmentation — As-Built Plan and Status

Last updated: 2026-11-02

This file records the delivered segmentation workflow and the current runtime
state. The operational runbook is [docs/customer_segmentation/README.md](docs/customer_segmentation/README.md).

## Delivered process

1. **Bronze source profiling:** Profiled
   `data/bronze/training_sample_50000.parquet`, a 50,000-building sample with
   419,750,000 hourly rows spanning 2018. The scan found 8,395 distinct
   timestamps per building, zero duplicate building/timestamp rows, and
   95.833% coverage of the 8,760-hour 2018 calendar window. There are five
   `GeneralUseType` categories: Residential 47,568; Commercial 1,585;
   Industrial 819; Institutional 27; Recreational 1.
2. **Feature generation:** Produced one feature row for every source building
   using 2018-01-01 inclusive through 2019-01-01 exclusive. All 50,000 buildings
   meet the 0.90 coverage threshold. Category values and geographic IDs are
   retained as metadata, not numeric clustering inputs.
3. **Modeling:** Compared supported K-Means and Gaussian Mixture candidates
   using internal fit metrics, stability, and minimum cluster-size checks.
   Residential, Commercial, and Industrial have independent models;
   Institutional and Recreational are pooled into `SHARED_SMALL_CATEGORIES`.
   All source-category assignments retain `GeneralUseType`.
4. **Publishing:** Wrote segment distribution/profiles, coarse and finer grid
   summaries, hourly/daily/monthly profiles, survey-priority rows, model
   metadata, and diagnostics. Survey scores use building consumption features
   and must not be read as grid/transformer risk assessments.
5. **MLflow:** The Airflow DAG registered the current bundles in the dedicated
   `gridvision-government-customer-segmentation` experiment. Exact model names,
   MLflow run ID, registry versions, and output validation are in
   `data/segmentation/reports/execution_summary.json`.
6. **Airflow:** The manually triggered DAG
   `government_customer_segmentation` completed successfully on
   `manual__2026-11-01T19:08:16+00:00`. During execution, Airflow was restarted
   after its scheduler was unavailable and this DAG was unpaused so it could
   process the queued run.
7. **UI/API:** The Government page is routed at
   `/app/government/segmentation`. Category filters use source
   `GeneralUseType`; the model group is separately visible. Region, priority,
   segment, and assignment views carry category filtering. The existing
   `/api/v1/customers/*` customer analytics remain separate.
8. **Operational documentation:** Run commands, outputs, API endpoints,
   registration names, model limits, and log locations are maintained in
   `docs/customer_segmentation/README.md`, linked from the root README and
   `logs/README.md`.

## Interpretation limits

- This run represents a 2018 sample and is not a current full building
  inventory.
- Cluster IDs and names describe unsupervised behaviour profiles; they do not
  establish customer intent, equipment faults, or grid reliability risk.
- Institutional and Recreational share a pooled model because their individual
  populations are small. The source category remains available in filters and
  assignment outputs.
- Internal clustering metrics and stability checks are not held-out predictive
  accuracy.
