# Example assistant questions

These are natural-language examples for `python -m ai.assistant`. The sample
plan generated by the forecasting pipeline is for `2018-09-25`; the hour
timestamps below are ISO 8601 and use the exact timestamps in that plan. If
your output directory contains a different date, substitute an available date
and timestamp. The assistant must clarify rather than fabricate unavailable
dates, hours, or grid IDs.

Run the interactive assistant once:

```bash
ollama serve
.venv/bin/python -m ai.assistant
```

Or send one question from the workspace root:

```bash
.venv/bin/python -m ai.assistant --query \
  "Show the next 3 hours of redistribution for grid 64 on 2018-09-25"
```

## 16 example questions

1. **Next-hour plan:** “Show the redistribution plan for 2018-09-25 at
   2018-09-25T00:00:00.”
2. **Next three hours:** “Show the next 3 hours of redistribution for grid 64
   on 2018-09-25.”
3. **Surplus and deficit:** “Which grids have surplus or deficit at
   2018-09-25T06:00:00 on 2018-09-25?”
4. **Transfer direction:** “Which grids supply grid 64, and how much do they
   send at 2018-09-25T06:00:00?”
5. **Transmission loss:** “What energy is lost to transmission at
   2018-09-25T06:00:00?”
6. **Single grid:** “Show the plan for grid 64 at 2018-09-25T12:00:00.”
7. **Compare two hours:** “Compare redistribution at 2018-09-25T08:00:00 and
   2018-09-25T09:00:00.”
8. **Unmet demand:** “Which grids still have unmet demand at
   2018-09-25T18:00:00?”
9. **Full-day summary:** “Summarize the complete 24-hour plan for 2018-09-25.”
10. **Technical deficit solution:** “How could the simulated remaining demand
    for grid 64 be reduced at 2018-09-25T18:00:00? Check direct neighbors.”
11. **Basic concept:** “What does transmission loss mean in this simulation?”
12. **Short conversation history:** After a successful plan question, ask
    “Regenerate the image for the last query.” This reuses the saved successful
    request's exact date, interval, and grid filter.
13. **Historical demand:** “Summarize historical demand for Grid 64 from
    2018-09-01 to 2018-09-30.”
14. **Saved-model prediction:** “Show the model-predicted demand for Grid 64
    on 2018-09-25.”
15. **Historical/model comparison:** “Compare historical and predicted demand
    for Grid 64 on 2018-09-25.”
16. **External research:** “Search the web for a recent energy demand forecast
    outlook and cite the sources.”

## Grid scope and artifact-only requests

The assistant recognizes grid IDs written as either `Grid 64` or `Grid64`.
For example:

```text
Which grids supply Grid 64 at 2018-09-25T06:00:00?
Show Grid 64's deficit at 2018-09-25T06:00:00.
Compare Grid 64 and Grid 72 at 2018-09-25T06:00:00.
```

Grid-level balance summaries include only the selected grid(s). Direct
neighbors are included in the plotted network and transfer endpoint context,
not silently added to the selected grid's totals. Network-wide questions
aggregate all 53 grids.

To request only an artifact, say for example:

```text
Generate only the image for Grid 64 at 2018-09-25T06:00:00.
Export only the CSV for Grid 64 at 2018-09-25T06:00:00.
Regenerate the image again.
Make the previous CSV again.
```

Artifact-only actions skip response generation and create no other artifact.
Follow-ups such as “show the next two hours,” “what about Grid 64?”, and “make
it simpler” reuse the preceding date/window as applicable. If a date or time
cannot be resolved from the question or recent history, the assistant asks for
clarification.

## Expected behavior

Substantive plan questions use the two separate configured LLM roles to
interpret and explain. Python validates the request against the available
simulation metadata, resolves timestamps, calculates summaries and any
technical direct-neighbor demand suggestion, and produces the image and CSV.
The assistant emits exact timestamps and data-backed values; it asks a
clarifying question for missing or ambiguous time/grid information. Basic
concept questions receive a concise explanation without requiring simulation
values. Demand-solution suggestions use only existing adjacent network edges,
remaining surplus, remaining edge capacity, and recorded loss percentages.
They describe technical feasibility only, not economic benefit or actual grid
operation.

All values, suggested transfers, capacities, connections, supply, and losses
are synthetic. They do not model real power lines, dispatch constraints,
economic cost, or operational controls.

Historical demand queries use only the 2018 historical dataset. Predicted
demand queries use the saved hybrid model and require feature rows for the
requested 24-hour day. Comparisons use only timestamps present in both the
historical observations and model forecast. External research is a separate
Tavily-backed response with source URLs; it does not change or augment
internally calculated energy values.

If a 2018 redistribution plan is missing, a date-only plan request generates
the full day from the saved model and passes it through the existing
redistribution pipeline. Cached predictions are reused when available. Ask for
an hour when you want a specific interval.

Multipart analysis can be requested in one question, for example:

```text
Give a historical analysis for Grid 64, generate its forecast, then compare
actual and predicted demand with WAPE on 2018-09-25.
```

The assistant computes each requested result independently. Comparisons align
by grid and timestamp, report WAPE with MAE/RMSE and MAPE, and disclose
incomplete coverage. Historical ranges are never widened to satisfy a
single-date forecast or comparison.

The default assistant uses locally downloaded Ollama models. Start the Ollama
service before running queries; the Ollama key file is not needed for local
inference.
