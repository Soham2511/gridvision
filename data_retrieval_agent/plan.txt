INDEPENDENCE

The module lives in data_retrieval_agent/ and does not import backend.app.ai. It calls existing non-AI services through injected adapters. The existing root plan.txt belongs to a different AI Layer project and is preserved. Existing routes/services were not rewritten; the two integration edits add the package blueprint and service construction to existing Flask wiring. No original datasets, trained models, or ETL were changed by this module.

1. AUDIT FINDINGS

- Flask app factory: backend/app/__init__.py. API v1 aggregate: backend/app/api/v1/__init__.py. Existing API uses Pydantic v2, JSON success/error envelopes, centralized logging, domain services and provider objects.
- Data provider abstraction exists, but its runtime choices are unavailable or test-only deterministic sample data. SampleDataProvider is synthetic illustrative data and is never used by the new tools.
- Existing service interfaces reused: CustomerBillPredictionService; TrainedForecastProvider; SegmentationService; AnomalyPredictionService. Model paths/provider approval gates are in backend/app/config.py and app factory. There is no new query engine or inference pipeline.
- Data is local Parquet/Gold/prepared output; bounded commercial/government reads use existing DuckDB interface; segmentation and anomaly use existing Pandas/PyArrow service interfaces. No live database schema/connection or live telemetry interface was found.
- No authenticated principal, identity provider, or server-side persona/entity authorization was found. The new Flask API therefore requires a host-installed `data_retrieval_identity_resolver(request)` returning AuthenticatedRequestContext; absent resolver yields 401. It never trusts request persona/entity as authorization.
- No authoritative company profile, equipment inventory, or operating-hours source/schema exists. Company tools are not registered and responses state that source is unavailable.
- LangGraph was already pinned in requirements-ai.txt; the runtime image now selects the new `agent` requirements group. Pydantic is provided by base requirements. Hosted and Hugging Face model clients are optional module dependencies.

3. APPROVED TOOL INVENTORY

- get_consumer_profile: Customer Gold profile for authorized residential consumer.
- get_historical_consumption: unified entity/cohort/region history tool; persona-specific window contract.
- get_building_details: commercial building profile from Commercial Gold.
- get_regional_information: authorized government grid catalog, filtered to scopes.
- get_energy_forecast: existing residential/commercial/government prediction service when model ready.
- get_anomaly_predictions: explicit consumer IDs and bounded date window; synthetic label carried in output.
- get_segmentation_results: existing consumer assignment, authorized regional aggregate, or government distribution.
- get_model_metadata: allow-listed model IDs via existing metadata services.

Company profile/equipment/operating hours are not registered because no authoritative source exists. Regional history/forecast/anomaly map to the unified history/forecast/anomaly tools to avoid duplicate responsibilities.

4. PERSONA AND AUTHORIZATION POLICY

No persona is trusted from request content. The host resolver must map verified principal to persona, permissions and entity scopes. Deny by default; tool visibility and execution both check permissions/source; handlers check persona/entity scope before service calls.

- Residential: own consumer profile/history/forecast/segmentation only; anomaly only for explicitly granted IDs and labeled synthetic.
- Commercial: assigned buildings/history/forecast; cohort history only with explicit wildcard cohort permission; company information unavailable.
- Government: authorized region/system history, catalog and segmentation; row-level consumer data only with separate explicit consumer scope. Synthetic anomaly access requires explicit consumer grants.
- Model metadata: allow-listed only, source availability checked.

A session binds principal/persona but does not retain or restore permissions. Every request resolves a fresh context and each tool checks again.

5. MODULE AND WORKFLOW

Package modules: config.py, context.py, schemas.py, tools/base.py, tools/schemas.py, tools/registered.py, services/adapters.py, providers/llm_provider.py, graph.py, agent.py, memory/session_manager.py and memory/checkpointer.py, api.py, docs, evaluation dataset/harness, and tests/data_retrieval_agent. The Flask blueprint is registered under `/api/v1/data-retrieval-agent`; the package API boundary uses local error/response contracts and does not import AI Layer code.

LangGraph steps: validate trusted request/session; source/permission-filter tools; coarse intent gate; LLM tool planning over only those schemas; Pydantic argument validation and handler authorization; bounded parallel independent execution; one conditional sequential follow-up round; output validation/provenance; answer generation with numeric fidelity guard; session checkpoint under opaque thread ID. Graph recursion, tool count, request timeout, date and input limits are configured. Provider retries are disabled. No SQL/Python execution is exposed.

LLM options: `hosted` (OpenAI-compatible) and `huggingface`, selected through GRIDVISION_RETRIEVAL_* settings; default is disabled/no provider. LangSmith tracing is optional/off by default. Credentials are environment-provided, not committed. No RAG/vector store is introduced.

6. API AND MEMORY

- POST `/sessions`: start opaque owner-bound session.
- POST `/sessions/{id}/messages`: send/continue validated message.
- GET `/sessions/{id}`: owner-only metadata.
- DELETE `/sessions/{id}`: clear session and graph thread.

In-memory manager and LangGraph InMemorySaver enforce idle/absolute expiry and process-local session isolation; conversation history is capped. Session context includes no grants. Worker restart loses sessions; multi-worker persistence needs a separate approved backend decision.

LangGraph conditional follow-up and parallel tool calls were executed with InMemorySaver in a unit test; it also verifies authorization data is absent from saved checkpoint state. The missing-source path and immutable authorization scopes are covered. 13 third-party deprecation warnings came from LangSmith internals under Python 3.15. Tests focus on the isolated module; the full pre-existing backend suite and production image were not run because the active venv is Python 3.15 and lacks the project's full backend/model-serving dependency set. No hosted model credentials or actual authenticated principal adapter are available for end-to-end live retrieval validation.

Evaluation dataset includes representative residential, commercial, government, company-source-unavailable, and synthetic anomaly prompts. `evaluation.py` reports tool selection accuracy, retrieval accuracy, tool execution success rate, response correctness, and unnecessary tool rate from annotated observed runs.

Remaining operational prerequisites: install/test on project Python 3.10 with full backend dependencies; configure a trusted identity resolver/entity grants; configure one LLM provider/model/credentials if the feature is to be enabled; verify actual source/model health. Company tools require a new approved authoritative source before implementation. Therefore this is an implemented isolated module, but cannot be described as production-ready or authenticated end-to-end in the current repository state.
